# 安全策略

## 当前状态

Protostar 尚未发布，也没有可运行的 server、worker 或界面。因此当前不存在可测试的运行时攻击面，也无法承诺安全支持窗口或已发布版本的修复周期。本策略用于约束当前仓库中的敏感信息处理，并为后续实现提供报告入口。

## 报告安全漏洞

**首选：GitHub 私密漏洞报告。** 如果本仓库已启用 GitHub 的私密漏洞报告（Private Vulnerability Reporting），请在仓库的 Security 页面选择「Report a vulnerability」提交。该渠道仅对维护者可见，便于在不公开细节的情况下讨论复现与修复。

**如果私密报告尚未启用：**

- 不要公开提交漏洞报告：不要在 Issue、Pull Request、Discussion 或任何公开渠道披露漏洞细节、可利用步骤、密钥、token、个人数据或私有代码。
- 在维护者公布可用的私密渠道之前，请暂缓提交完整报告并保留细节；可关注仓库 Security 页面或维护者后续的公开说明。
- 不要猜测或使用未公开的邮箱、即时通讯或其他联系方式；本文件不提供、也不虚构安全联系地址。

若问题涉及已经泄露的凭据，请在可行的情况下先自行轮换，不要在公开内容中引用旧凭据。

## 报告应包含

- 受影响的模块、文件、版本或 commit。
- 问题类型与影响：例如权限绕过、凭据泄露、审批伪造、跨组织数据读取、命令执行、拒绝服务。
- 可复现的前提与最小步骤；只使用你自己的测试环境。
- 期望结果与实际结果。
- 是否涉及真实用户数据或密钥；如涉及，只描述类型，不粘贴原值。
- 可选的修复建议。

请勿对不属于你的部署、账户或数据进行测试；不要为了验证问题而读取、修改或删除他人数据。

## 处理方式

维护者会审阅报告，确认影响范围，并在可行时安排修复与协调披露。披露时间以修复可用性与双方沟通为准；在修复发布前，请避免公开细节。本文件不承诺响应时限、修复期限、漏洞奖励或任何形式的赔偿。

如果报告不属于安全问题，维护者可能建议改为普通 Issue 讨论。

## 敏感资料范围

以下内容不得提交到仓库、Issue、PR、Discussion 或文档示例中：

- 模型 provider 的 API key、访问 token 与计费凭据。
- worker 注册凭据、任务租约 token、服务身份凭据。
- OAuth／OIDC 的 client secret、授权码、refresh token 与会话 cookie。
- 私有仓库内容、未公开的代码差异、个人数据与私人对话记录。
- 项目知识库正文、知识 bank 凭据与外部知识服务的全局密钥。
- 含上述内容的完整日志、环境变量导出或终端记录。

如需展示配置形式，请使用明显无效的占位值，并说明它不是真实凭据。

## 后续实现的安全重点

当实现交付后，安全审阅应重点关注：组织与项目的数据隔离、审批版本绑定、worker 租约与过期报告拒绝、外部集成凭据的保存与撤销、事件与日志脱敏、模型与知识服务调用的数据范围。这些能力目前尚未实现，不能以文档描述视为已具备。
