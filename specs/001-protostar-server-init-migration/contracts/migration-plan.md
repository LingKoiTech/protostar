# 六模块迁移计划记录字段规则

**Status**: 随 [plan.md](../plan.md) 一并待 HumanMiao 审批。

**记录规则性质**: 本文件是 001 规划记录的内容规则，不是运行时 API、数据格式、CLI 参数或数据库 schema。它规定六模块迁移矩阵的字段、证据规则与禁止项，供主线程审核、tasks 派生与 HumanMiao 审批使用。运行接口由 002–031 各自的 spec／plan 定义。

**覆盖对象**: `protostar_server`、`protostar_worker`、`protostar_cli`、`protostar_mcp`、`protostar_skills`、`protostar_gui`。

**字段基数**: 每个模块必须填写十一项语义：FR-006 的十项要求，加上 [spec.md](../spec.md) Key Entities 要求的“批准版本与证据”。其中“数据／API／session 权威”作为一项填写，不得分成三份互相矛盾的声明。

## 1. 字段规则

| 序号 | 语义 | 必填内容 | 证据规则 | 禁止 |
|---|---|---|---|---|
| 1 | 能力 | 模块承担的业务与技术能力 | 引用 spec 模块表、[PRD.md](../../../docs/PRD.md) 章节与负责版本 | 用“等”“相关能力”概括到无法核对 |
| 2 | 实际实现来源 | 本仓是否有代码；无代码时列出所读行为来源与章节 | 明确写“无本仓代码”或给出后续版本才产生的证据；不得写不存在的代码路径 | 编造文件、模块、进程、运行记录 |
| 3 | 目标模块 | 六模块中的唯一归属与目录状态 | 对照仓内目录事实与 [spec.md](../spec.md) FR-005 | 把空目录写成已运行服务 |
| 4 | 数据／API／session 权威 | 该模块对哪些对象有写权威、哪些只读或投影 | 引用 PRD §4.3、§7.4、§8.2；声明唯一权威 | 同一对象出现两个写权威；客户端保存业务真源 |
| 5 | 保留或替代 | 历史行为保留、代码替代、可选导入的边界 | 引用 PRD §3.2、§3.3 与 spec FR-009 | 声称已迁入历史代码或已导入数据 |
| 6 | 依赖 | 上游服务、版本、外部连接与配置 | 引用 PRD §15、§15.1 与对应版本 | 把未批准能力当作既有依赖 |
| 7 | 验收 | 该模块在哪些版本以什么真实证据验收 | 每项给出负责版本与验收类别；001 只做文档核对 | 以模拟输出、空产物、目录或文档代替验收 |
| 8 | 停机或并行切换边界 | 是否需要停机、切换前置、禁止双写的条件 | 当前无旧端进程时明确“无需当前停机”；031 才有条件切换 | 设计长期双写或未批准的切换 |
| 9 | 失败处理 | 错误保留、停止范围、外部副作用与恢复规则 | 引用 PRD 对应章节与 constitution IV | 静默成功、自动重放远端副作用、伪造恢复 |
| 10 | 旧系统退出条件 | 停止写入、调用方切换、凭据移除、历史只读的判据 | 引用 PRD §3.3 与 spec FR-009 | 提前宣告旧端退出或保留第二权威 |
| 11 | 批准版本与证据 | 001 plan 状态与各实施版本的批准／验收引用 | 只引用真实存在的审批对象与版本；批准栏空白时写待批 | 代理批准、虚构批准人或日期、把文档完成写成产品完成 |

## 8. 跨模块权威规则

| 对象类别 | 唯一写权威 | 消费与投影 | 切换规则 |
|---|---|---|---|
| 用户、组织、项目、需求、产物版本、审批 | `protostar_server` | CLI／MCP／GUI 经 API；skills 经 CLI | 项目级切换后旧端不再写入 |
| 节点、边、图变更、任务派发与租约 | `protostar_server` | worker 领取与回报；GUI 读取 | worker 不写业务图 |
| 运行投影与事件历史 | `protostar_server` | GUI／CLI 读取；MCP 经 server | worker 提供原始事件，不修改历史 |
| 活进程与后端 session | `protostar_worker` | server 保存投影；人类经 server 发起控制 | 不由 server 直接接管本机进程 |
| 知识正文与派生关系 | Hindsight | server 保存绑定；GUI／CLI 经 server | 不复制知识数据库 |
| 代码索引与查询结果 | CodeGraph（worker 侧调用） | server 保存引用与版本 | 索引不进入业务库 |
| 界面状态 | `protostar_gui` 仅展示 | 不跨组织复用缓存 | 切换组织时清理客户端内容 |
| 审批决定 | `protostar_server` 记录，HumanMiao 产生 | Agent 只能请求，不能批准 | 绑定对象版本与 SHA |

## 9. 切换与失败规则

1. 本仓当前没有旧端进程，因此不存在当前停机窗口；任何“停机”表述仅适用于 031 获批后的项目级迁移。
2. 切换前置：组织与项目归属确认；记录数量、依赖、产物与未确认报告核对；在途工作完成或人类终止；调用方清单齐备。
3. 切换顺序：暂停旧端新任务领取；冻结并核对；切换 worker、CLI、MCP、skills、GUI 配置；server 成为唯一写入；旧端移除写入入口、调度与凭据。
4. 禁止事项：双写、自动重放有远端副作用的操作、以新执行冒充恢复、未批准的数据导入。
5. 失败处理：在发生位置保留原因并停止受影响操作；区分环境、权限、外部服务与产品缺陷；旧尝试不能覆盖新尝试；由人类决定修复或受控恢复。
6. 旧端退出：迁移项目停止写入、历史只读、凭据撤销、调用方全部切换；未完成迁移的项目继续留在原系统，不进入双写状态。
